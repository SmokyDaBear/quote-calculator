# feature updates:

This is a feature list of things to be added/updated

## Appointments

Allow a quote to be rolled to an appointment.
The appointments table should store:

- Date and time Created
- Date and time of dropoff/appointment
- Promised By time and date
- Customer ID
- Quote ID
- Transport type (Waiter, Drop-Off, Loaner, Shuttle, undefined)

# Sublets

Allow creation of sublet lines on a quote, or order with a markup matrix just like the labor/parts matrix (adjustable in settings) and overrideable for a custom value (warn if below cost).

store:

- cost
- vendor
- sellPrice

**Note** in most states, sublets are not taxable, so it depends on the users state/city. Add in laborTax item under global rates settings for states that have this rate.

Sublets should be able to link to a vendor invoice/purchase order (for orders, quotes are just quotes).

## Purchase Orders

Purchase orders functionality needs to be added in.

Functionality for inventory tracking with bin locations and quantity on hand, quantity available (on hand minus amount on open orders).

Then allow purchase order creation and receiving.

Not all purchase orders will have items that will be put in inventory, some are consiidered shop supply and are not inventoried, and some will be for shop maintenance, and others are sublets.

Allow a sublet to be linked to an order (for instance a detail from another shop) which links the po to the sublet on the order for record keeping.

After selecting vendor for a purchase order allow user to add:

- an item from inventory to restock when adding items to an order, which automatically updates quantity when received.
- a sublet (which should be able to be done from the work order screen and links to the order).
- a special ordered part (which creates an inventory item with automatic matrix pricing OR if the user already has a price on the part in the order, that will be used as a menu price for the inventory item)
- or allow a shop to create custom expenses that can be tracked over time, for instance:
  - landscaping
  - site maintenance like plumbing or electrical repairs
  - store meetings
  - store parties
  - training
  - internet/it expenses
  - shop security
  - insurance
  - uniforms
  - janitorial
- add a misc charge/shop supplies with a note (like brake clean, towels, hardware etc. that is not tracked in inventory)

### Inventory Update

Add quantity on hand, quantity available(total minus the sum of quantities from the job_parts table matching the inventory id) and bin-location tracking on parts.

Upon receiving parts from a purchase order, the parts should be able to be added to inventory (update quantity on hand) if applicable (optional since they might be miscellaneous, or a sublet/labor operation).

## Order Creation, Invoicing, and Payments

the quote system needs to be able to transform a quote into an appointment or order, and then creating an invoice when completed and adding payment. This is all completely local, so the payments will just be a record, but add ability for: cash, check (with check number), charge (with customer P.O., paid_at, billed_at).

The orders table should have:

- orderId
- vehicleId
- customerId
- mileageIn
- mileageOut
- transportType
- quotedTotal(subtotal of parts and labor from all jobs initially quoted before creation (no tax or shop fees))
- shopCharges
- taxTotal
- orderSubtotal (updated based on actual current total regardless of quoted price and includes sublets, but NOT tax or fees(stored separate).)
- discountAmount (amount of discount if applicable)
- createdAt
- upatedAt
- invoicedAt
- voidedAt (orders shouldn't technically be able to be deleted, but can be voided if customer leaves after order creation but before work is done)
- finalized (boolean if order has been invoiced, and billed in which case it should no longer be able to be edited (including jobs for the order)), paidInFull (whether order has been paid)

Jobs for an order should be stored in a separate table referencing the orderId. Jobs will contain:

- orderId
- id
- opCode (null for custom recommendations)
- laborHours
- laborPrice
- quotedLaborPrice and quotedPartsPrice(not-editable and goes from whenever the job was initially approved or from the quote if rolled from quote or appointment)
- partsTotal
- addOn?(boolean if job is an initial concern which is if it was created when order was made or if added on after by a recommendation)
- payType (warranty(manufacturer warranty), customer pay(normal pay type), internal(for warranties by the shop itself))

Then a jobParts table with:

- orderId
- jobId
- inventoryId
- quantity
- unitPrice
- estimatedTimeOfArrival (for special ordered parts)

## Customer Updates

Show customer's outstanding balance (get total from all invoices with customer id, and all payments with customer id and get difference positive for over payment (or credit), and negative for amount due). Also, when a user is adding customer info to the quote screen, allow them to create a new customer/ save customer after filling the form.

Saving a customer should set the selectedCustomer to the created one which should show the details component (with list of vehicles and ability to add vehicle) this will prevent having to immediately search for them in order to add a vehicle.

Show order history for a vehicle, should be available on quote screen, customers screen => vehicles => selectvehicle, and on the vehicles screen.

Allow searching by VIN on the quote screen (in addition to the current name and phone number search) to pull up vehicle details and auto-populate the customer and vehicle information from storage (if already in system)
